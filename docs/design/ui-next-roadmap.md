# UI 下一步规划（设计审视 · 突破现有体系）

> 日期：2026-09-19 ｜ 分支：master @ `fde9e22`（已推送）
> 方法：product-design **audit** 路径 + 阅读主路径 UX 审视；刻意跳出「液态玻璃 token 体系」看产品。
> 本文是规划，不是实现 spec。选定方向后再开 compose 轮。

## 体验现状（一句话）

壳层像一套精致的「玻璃展示柜」，书只是柜里的展品——气质到位，但**阅读任务的层级仍弱于材质系统本身**。

## 系统级局限（不是像素 bug）

1. **材质即 IA** — 玻璃参数、霜层、色渗与阅读默认同权；系统在优化「怎么看壳」，不是「怎么读完一本书」。
2. **签名与核心倒挂** — 近轮 compose 集中在设置玻璃；阅读 chrome、续读信息层仍薄。
3. **平台身份分裂** — Windows `forceLite` + 双参数档，桌面/移动像两套产品；玻璃可降级，产品语言不应双轨。
4. **动效语法碎片** — 槽位缩放、FLIP、FrostGate 320ms、Tab slide、层级 Fade 各自为政，缺统一「谁在动 / 为何动 / 可否关」。
5. **空态与假入口** — 书源近空壳、hub 占位项、空架只有描边图标。
6. **移动壳硬套桌面** — 可扩展胶囊底栏是手机手势语言；Windows 应侧栏/多栏/快捷键，不是更大圆角。

## 对标启发（借模式，不抄皮）

| 产品 | 可借的模式 |
|------|------------|
| Kindle / Apple Books | 「继续阅读」永远第一屏；进度是主视觉，chrome 可消失 |
| 微信读书 | 书架信息层用时长/笔记密度，而非材质层 |
| Craft / Obsidian | 文档是材料，工具栏静默；桌面多栏 |
| Material You 设置 | 玻璃只属浮层 chrome，列表本体 tonal 纸面（与 DESIGN.md 原则一致，尚未成为全 app 纪律） |

阅读路径另审结论（高杠杆）：

- **菜单收束为会话驾驶舱** — 贴底 sheet 一屏：进度 / 章导航 / 字号 / 夜间；深设置退回全局默认。
- **Chrome 律法** — 正文恒纸色；工具层一次性浮现，阅读手势即退场。
- **拇指弧** — 主操作下移底弧；顶栏只负责「我在哪」；退出与目录常驻可达。
- 返回书架目前固定落首位，与「从哪来」槽位缩放叙事不一致（可列为后续）。

## 路线图（约 4–8 轮 compose）

| 优先级 | 主题 | 目标 / 形态 | 明确不做 |
|--------|------|-------------|----------|
| **P0** | 书架任务层 · 续读主卡 | 打开即续读：首屏固定卡（封面侧影 + 章名 + 进度 +「继续阅读」）；无进度书回落网格 | 再调封面光效 / 玻璃参数 |
| **P0** | 设置 IA 减负 | 阅读相关升权、材质降权：根页「阅读」优先；材质收进「高级 · 外观」；删假入口 | 新增材质参数字段 |
| **P1** | 阅读 chrome 契约 | attached sheet 驾驶舱 + 顶栏雾规范；正文永不玻璃化 | 整页 BackdropFilter |
| **P1** | 动效系统表 | 一张 duration/curve/可关策略表，壳/设置/阅读共用 | 新炫技转场 |
| **P2** | 空态与书源 | 无书导入引导、坏源可行动 | 完整书源商城 |
| **P2** | Windows 壳 | 可选侧栏 + 列表/网格密度；lite 玻璃仅作 chrome 选项 | 为桌面重写液态引擎 |

## 建议下一轮只做一个

**书架「继续阅读」主卡（P0）**

- 打开书架，首屏最显眼是一张**任务驱动**的续读卡：当前书 + 章名 + 进度 + 主按钮「继续阅读」。
- 点击直达上次阅读位置；无阅读进度则不出现该卡，回落现有网格。
- 底栏 / 玻璃 token **本轮不动**——把视觉主角还给书。

验收草图：热启动书架 → 0.5s 内看到续读卡 → 一键进书且落在上次位置；空进度用户无感差异。

## 工程约束（规划时记住，实现时再收紧）

- Impeller：同一时刻底栏只挂一层 Lens（ExpandableGlassNav 契约）。
- 玻璃只属 chrome（DESIGN.md）；阅读正文禁止玻璃化。
- 转场三套已交付：层级 Fade / Tab 方向 slide / 书架槽位缩放——新 UI 勿再发明第四套，先并入动效表。
- compose 流程不变：选定方向 → grill（若歧义）→ spec → 实现 → 真机 → push。

# Bug 修复报告：file_picker 12.x API 破坏性变更（`FilePicker.platform` 移除）

## 修复日期
2026-08-29

## 问题概述

升级 `file_picker: ^8.1.6` → `^12.1.2`（最新版）后，Dart 端调用 `FilePicker.platform.pickFiles(...)` 编译失败：

```
lib/main.dart:158:39: Error: Member not found: 'platform'.
      final result = await FilePicker.platform.pickFiles(
                                      ^^^^^^^^
Target kernel_snapshot_program failed: Exception
```

**触发条件**：升级到 `file_picker >= 12.0.0`（melos monorepo 拆分版本）。

## 根本原因

**`file_picker 12.x` 引入 plugin federation 架构**——Android 实现拆到独立包 `android_file_picker`：

```yaml
# file_picker 12.1.2 pubspec
dependencies:
  file_picker_platform_interface: ^3.2.0
  android_file_picker: ^1.0.0    # 拆出
  file_picker_darwin: ^1.0.4
  file_picker_linux: ^1.0.0
  windows_file_picker: ^1.0.0
  file_picker_web: ^3.0.0

flutter:
  plugin:
    platforms:
      android:
        default_package: android_file_picker  # 关键：federation 模式
      ios:
        default_package: file_picker_darwin
```

**`FilePicker` 类的设计变化**（`packages/file_picker/lib/src/file_picker.dart`）：

- **10.x**：`FilePicker` 是**单例接口**，通过 `FilePicker.platform` 暴露 `FilePickerPlatform.instance`
- **12.x**：`FilePicker` 改为**抽象 final 类**，直接提供静态方法（如 `pickFiles()`），内部仍调 `FilePickerPlatform.instance`

```dart
// 12.x 实际定义（lib/src/file_picker.dart）
abstract final class FilePicker {
  static Future<List<PlatformFile>> pickFiles({...}) {  // 静态方法，不再走 .platform
    return FilePickerPlatform.instance.pickFiles(...);
  }
  // pickFile / getDirectoryPath / saveFile / clearTemporaryFiles 等
}
```

**返回类型破坏性变化**：
- **10.x**：`pickFiles()` 返回 `Future<FilePickerResult?>`——`FilePickerResult.files: List<PlatformFile>`
- **12.x**：`pickFiles()` 返回 `Future<List<PlatformFile>>`——**直接返回文件列表**，无中间 `FilePickerResult` 包装

**用户取消判定变化**：
- **10.x**：`result == null`
- **12.x**：`files.isEmpty`

**单文件访问变化**：
- **10.x**：`result.files.single`
- **12.x**：`files.first` / `files[0]` / `files.single`

## 解决方案

**不降版本**——按用户要求采用最新版 API，**改 `lib/main.dart` 一处调用**：

```dart
// 之前（10.x）
final result = await FilePicker.platform.pickFiles(
  type: FileType.custom,
  allowedExtensions: ['txt', 'epub'],
);
if (result != null && result.files.single.path != null) {
  final filePath = result.files.single.path!;
  final fileName = result.files.single.name;
  // ...
}

// 之后（12.x）
// file_picker 12.x: FilePicker.pickFiles() 直接调用（不再走 .platform），
// 返回 List<PlatformFile>（空列表 = 用户取消）
final files = await FilePicker.pickFiles(
  type: FileType.custom,
  allowedExtensions: ['txt', 'epub'],
);
if (files.isNotEmpty && files.first.path != null) {
  final filePath = files.first.path!;
  final fileName = files.first.name;
  // ...
}
```

**仅 `lib/main.dart:158-165` 8 行**——业务逻辑（book name 提取、Navigator.push）零变化。

## 完整 10.x vs 12.x API 映射

| 调用 | 10.x | 12.x |
|---|---|---|
| 单文件选择 | `pickFiles(allowMultiple: false)` 返回 `FilePickerResult` | `pickFile()` 返回 `PlatformFile?`（**新方法**） |
| 多文件选择 | `pickFiles()` 返回 `FilePickerResult?` | `pickFiles()` 返回 `List<PlatformFile>`（空 = 取消） |
| 目录选择 | `getDirectoryPath()` 返回 `String?` | `getDirectoryPath()` 返回 `String?`（不变） |
| 保存文件 | `saveFile()` 返回 `FilePickerResult?` | `saveFile()` 返回 `Uri?`（**类型变 Uri**） |
| 临时文件清理 | `clearTemporaryFiles()` | `clearTemporaryFiles()`（不变） |
| 平台跳过 | N/A | `skipEntitlementsChecks()`（macOS 专用，**新方法**） |
| Android SAF 配置 | `androidSafOptions` | `androidOptions`（**新参数，类型 `AndroidOptions`**） |
| Windows 锁父窗 | `lockParentWindow` | `WindowsOptions.lockParentWindow` |
| Web 取消上传 | `cancelUploadOnWindowBlur` | `WebOptions.cancelUploadOnWindowBlur` |
| Darwin 压缩 | `compressionQuality` | `compressionQuality`（不变） |
| Deprecated 参数 | N/A | `allowMultiple` / `withData` / `withReadStream` / `readSequential` 全部 `@Deprecated` |

**保留行为**：
- Android 13+ 用 SAF/PhotoPicker，**无运行时文件权限**
- Android 12- 用 `ACTION_OPEN_DOCUMENT` (SAF)
- iOS/macOS/Windows/Linux/Web 各自原行为

## 备选方案（已弃用）

### 方案 B：降到 `file_picker: ^10.3.10`

**保留 10.x 的 `FilePicker.platform` API**——业务代码不动。**已临时采用过**，但**用户明确要求不修改业务代码而采用最新版本**。**最终回退到 12.1.2 + 改 main.dart**。

### 方案 C：保留 8.3.7

**问题**：8.3.7 的 `build.gradle` **没指定 compileSdk**——AGP 9 严格校验会失败。**不可行**。

## 预防/工程约束

**`file_picker` 主版本升级检查清单**：
1. `pubspec.lock` + `pubspec.yaml` 锁定到具体 minor 版本（如 `^12.1`）——避免 minor 升级打破 API
2. 每次升级看 CHANGELOG 里的 "BREAKING" 段——12.x 必看
3. `FilePicker.platform` 这种"平台单例"模式**易被重命名**——业务代码最好封装一层 `FileService.pickBook(context)`，避免直接调 `FilePicker` API，升级时只改 service 一处
4. federation 拆分后 Android 单独装 `android_file_picker` 包——但**API 层 `FilePicker.pickFiles` 仍可用**（federation 在 build 阶段透明，运行时通过 `FilePickerPlatform.instance` 调度）

**Plugin federation 模式**：12.x 拆 `android_file_picker` 是行业趋势（避免单仓多平台代码混杂）。**未来升级留意**：`path_provider`、`shared_preferences` 等都可能走这条路。

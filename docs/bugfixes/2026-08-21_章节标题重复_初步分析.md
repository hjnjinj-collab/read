# 修复：章节标题重复显示问题

> **修复时间**: 2026-08-21 17:00  
> **问题**: 章节内容中重复显示标题，且章节结束后紧接下一章内容  
> **状态**: ✅ 已修复并通过编译验证

---

## 问题描述

用户反馈的问题：
1. **章节内容中重复显示标题** - 标题在章节内容开头重复出现
2. **章节边界处理错误** - 左右翻页时，一页章节结束后紧接着显示下一章内容

## 根本原因

### 问题分析

在章节提取逻辑中（`extract_chapters_mmap()` 和 `extract_chapters_static()`）：

```rust
// 旧代码（错误）
chapters.push(RawChapter {
    title: trimmed.to_string(),
    start_pos: line_start,  // ❌ 指向标题行的起始
    end_pos: 0,
});
```

这导致：
- `chapter.start_pos` 指向标题行的起始位置
- 读取章节内容时会包含标题行
- 章节内容 = 标题 + 正文 ❌

### 期望的行为

```
文件内容：
第1章 开始      ← 标题行（line 0）
这是第一章内容   ← 内容行（line 1）
更多内容        ← 内容行（line 2）
第2章 继续      ← 下一章标题（line 3）
```

**期望**：
- 第1章内容应该从 line 1 开始（不包含标题）
- 第1章内容应该在 line 3 之前结束（不包含下一章标题）

**实际（修复前）**：
- 第1章内容从 line 0 开始（包含标题 ❌）
- 第1章内容在 line 3 之前结束（正确 ✅）

---

## 修复方案

### 修改内容

让章节的 `start_pos` 指向标题的**下一行**，而不是标题行本身。

### 修改位置

**文件**: `rust/crates/book_parser/src/txt_parser.rs`

**方法1**: `extract_chapters_mmap()` (第932-941行)
**方法2**: `extract_chapters_static()` (第766-775行)

### 修改前后对比

#### 修改1: extract_chapters_mmap()

```rust
// 修改前
if prev_line_is_blank && next_line_context {
    chapters.push(RawChapter {
        title: trimmed.to_string(),
        start_pos: line_start,  // ❌ 包含标题
        end_pos: 0,
    });
}

// 修改后
if prev_line_is_blank && next_line_context {
    // 计算标题行的结束位置（标题行起始 + 标题长度 + 换行符）
    let title_line_end = line_start + line.len() + 1;
    
    chapters.push(RawChapter {
        title: trimmed.to_string(),
        start_pos: title_line_end,  // ✅ 从标题下一行开始
        end_pos: 0,
    });
}
```

#### 修改2: extract_chapters_static()

```rust
// 修改前
if prev_line_is_blank && next_line_context {
    chapters.push(RawChapter {
        title: trimmed.to_string(),
        start_pos: current_byte_pos,  // ❌ 包含标题
        end_pos: 0,
    });
}

// 修改后
if prev_line_is_blank && next_line_context {
    // 计算标题行的结束位置（当前位置 + 行长度 + 换行符）
    let title_line_end = current_byte_pos + line.len() + 1;
    
    chapters.push(RawChapter {
        title: trimmed.to_string(),
        start_pos: title_line_end,  // ✅ 从标题下一行开始
        end_pos: 0,
    });
}
```

## 修复后的行为

### 数据流

```
1. 章节识别
   ↓
识别到标题: "第1章 开始" (字节偏移 0)
   ↓
计算标题结束位置: 0 + 行长度 + 1 = title_line_end
   ↓
章节起始位置: title_line_end (指向下一行)
   ↓
章节结束位置: 下一章标题的起始位置
   ↓
章节内容: [title_line_end, next_chapter_start) ✅ 不包含标题
```

### 示例

```
文件内容（字节偏移）：
0:  "第1章 开始\n"      (15字节)
15: "这是第一章内容\n"   (21字节)
36: "更多内容\n"        (13字节)
49: "第2章 继续\n"      (15字节)

修复后：
- 第1章 start_pos = 15  (标题后的位置)
- 第1章 end_pos = 49    (下一章标题的起始)
- 第1章内容 = content[15..49] = "这是第一章内容\n更多内容\n"
  ✅ 不包含标题 "第1章 开始"
  ✅ 不包含下一章标题 "第2章 继续"
```

## 关于"下一章内容紧接"的问题

### 问题分析

如果用户仍然看到"一页结束后紧接下一章内容"，可能是以下原因：

1. **分页器问题**（Flutter 侧）
   - 分页器在章节边界处没有正确处理
   - 一页内容显示了多个章节

2. **章节边界计算**
   - 当前实现：`chapters[i].end_pos = chapters[i + 1].start_pos`
   - 这是正确的：当前章节结束在下一章标题的起始
   - 修复后：由于 `start_pos` 现在指向标题的下一行，所以 `end_pos` 会指向下一章标题行的起始
   - 需要调整：`end_pos` 应该指向下一章标题的下一行吗？❓

### 需要进一步确认

**当前逻辑**：
```rust
// 设置结束位置
for i in 0..chapters.len() {
    if i + 1 < chapters.len() {
        chapters[i].end_pos = chapters[i + 1].start_pos;  // 下一章的内容起始
    } else {
        chapters[i].end_pos = file_size;
    }
}
```

**问题**：
- 第1章 end_pos = 第2章 start_pos = 标题2的下一行
- 这意味着第1章内容会包含第2章的标题行 ❌

**解决方案**：
我们需要记录标题行的位置，然后设置 `end_pos` 为标题行的起始。

## 可能需要的进一步修复

### 如果问题仍然存在

需要修改章节结束位置的计算逻辑，确保 `end_pos` 不会包含下一章的标题。

**方案A**: 在提取章节时记录标题位置
```rust
struct RawChapter {
    title: String,
    title_pos: usize,    // 标题行的起始位置
    start_pos: usize,    // 内容起始（标题下一行）
    end_pos: usize,
}

// 设置结束位置
chapters[i].end_pos = chapters[i + 1].title_pos;  // 结束在下一章标题之前
```

**方案B**: 在 `build_cleaned_chapter_cache()` 中处理
```rust
// 章节结束：下一章标题的行号（不是标题的下一行）
let end_pos = if idx + 1 < self.chapter_metadata.len() {
    mapper.map_line_to_offset(self.chapter_metadata[idx + 1].line_number)
    // 而不是 line_number + 1
} else {
    cleaned_content.len()
};
```

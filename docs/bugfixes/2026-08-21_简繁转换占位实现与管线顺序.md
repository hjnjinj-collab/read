# 简繁转换占位实现与管线顺序修复

> 日期: 2026-08-21
> 症状关键词: 简繁切换不生效 / 替换规则不生效 / 设置需要重启才生效 / 内容处理设置

---

## 症状

用户在阅读页打开「内容处理设置」，切换简繁转换或添加替换规则后点「应用设置」，
返回阅读页内容毫无变化；重启应用后才（看似）生效。

## 根因（三层叠加）

### 1. 转换本身是占位实现（核心）

两条链路的简繁转换都从未真正实现：

- **阅读级** `reader_core::content_preprocessor::s2t/t2s`：
  仅 9 个词的 `.replace()`（简体→簡體、设置→設置……）。
  正常小说正文不含这些词 → 切换后文本逐字节相同。
- **导入级** `book_parser::content_cleaner::convert_text`：
  整个函数是 TODO 桩，直接返回原文并打 warn 日志。

此前 BUG_FIXES §2 的诊断「预处理器未被调用」只对了一半：
调用接通后，转换内部仍是空操作——**开关传到了，但引擎没装发动机**。

### 2. 对话框不回读当前设置

`ReaderSettingsDialog` 的本地状态全部初始化为默认值（不转换、无规则）。
用户第二次打开对话框再点「应用」时，会用默认值**覆盖**上次的设置，
表现为"设置总是丢/不生效"。

### 3. 应用流程双重加载竞态

`_applySettings` 先后调用 `updateContentSettings`（触发一次未 await 的重载）
和 `updateCleaningSettings`（又触发一次），两次 FFI 重载并发竞争最终页面状态。

## 修复

1. **引入 zhconv 0.4.1**（纯 Rust，内嵌 OpenCC/MediaWiki 词组级表，静态初始化一次）。
   新增全项目唯一权威实现 `book_parser::chinese_convert::{convert_s2t, convert_t2s}`；
   阅读级预处理与导入级净化均委托它，保证两链路行为一致。
   词组级转换同时修正了单字映射无法处理的歧义词（头发→頭髮 / 发展→發展）。
2. **管线顺序调整**：替换规则移到简繁转换**之前**。
   用户规则按书籍原文书写，若先转换（敏感词→敏感詞）规则将永远无法命中；
   转换放在最后一步，对含规则替换后的完整文本生效。
3. **对话框回读**：`initState` 从 provider getters 读当前生效配置。
4. **统一应用入口**：新增 `applyContentProcessingSettings()`，
   更新选项 → `updateBookCleaning` 失效缓存 → 单次带锚点重载，消除竞态。

## 验证

- 新增集成测试 `bridge/tests/runtime_settings_apply.rs`：
  通过与 FFI 完全相同的 `get_page_processed` 入口断言
  s2t 即时生效、替换规则即时生效、options_hash 缓存隔离互不污染。
  （该测试在修复前失败：s2t 后文本与基线完全相同——精确复现用户症状。）
- `cargo test --workspace` 全绿；`flutter analyze` 无错误。

## 追加（同日）：规则替换"保存了却不生效"

后端链路经完整应用序列测试证实正常
（`app_flow_rules_apply_after_update_cleaning`：带净化解析 →
update_book_cleaning → 带锚点加载，规则生效）。
实际根因在对话框交互：

1. **输入框与规则列表分离**：用户填完「要替换的文本/替换为」后直接点
   「应用设置」，未先点「添加规则」按钮 → 规则静默丢弃。
   修复：`_applySettings` 先执行 `_collectPendingRule()` 收编输入框内容，
   SnackBar 回显「替换规则 N 条」供确认。
2. **翻页计数缺参数**：`nextPage/previousPage` 调 `getPageCountProcessed`
   未传 replaceRules，与内容路径（带规则）分页结果不一致，
   章节末页判断可能错位。修复：两处补传 `_replaceRules`。

## 工程约束（新增）

- **替换规则必须先于简繁转换执行** —— 规则按原文书写。
- **显示层转换与结构净化共用同一权威实现** —— 两套实现必然漂移。

# Bug 修复报告：书架唯一约束冲突（重开书籍必崩）

## 修复日期
2026-08-22

## 问题概述

打开任何一本**已入库**的书籍时，阅读页直接显示错误：

```
Error: SqliteException(2067): while executing statement, UNIQUE constraint failed:
books.file_path, constraint failed (code 2067)
  Causing statement: INSERT INTO "books" ("file_path", "title", "last_read_at")
  VALUES (?, ?, ?) ON CONFLICT("id") DO UPDATE SET "file_path" = ?, "title" = ?, "last_read_at" = ?
```

**影响范围**：重开任何书架书籍必现（不止重复导入）；书架持久化完全失效。

## 根本原因

`app_database.dart` 的 `Books` 表：`id` 为自增主键，`filePath` 为**独立的** UNIQUE 列。
`upsertBook` 使用 drift 的 `insertOnConflictUpdate`，它生成的冲突子句是
`ON CONFLICT("id") DO UPDATE`——只覆盖**主键**冲突。

而 `book_id` 每次解析都重新生成（自增 id 恒为新值，见表注释「跨启动恢复只能依赖
文件路径」），INSERT 永远不会撞 id，只会撞 filePath 的 UNIQUE 约束 → 2067。

## 解决方案

drift 定向 upsert：显式声明冲突目标为身份键列。

```dart
await into(books).insert(
  BooksCompanion.insert(filePath: filePath, title: title, lastReadAt: Value(DateTime.now())),
  onConflict: DoUpdate(
    (old) => BooksCompanion(title: Value(title), lastReadAt: Value(DateTime.now())),
    target: [books.filePath],   // 冲突目标 = filePath 唯一约束
  ),
);
```

命中已有 filePath 时更新 title/lastReadAt，否则正常插入；id 冲突场景不存在
（自增恒新），无需额外覆盖。

## 预防/工程约束（新增）

**drift 的 `insertOnConflictUpdate` 只对主键生效**——表若存在其他 UNIQUE 列
且以该列作为业务身份键，必须用 `insert(onConflict: DoUpdate(..., target: [列]))`
显式指定冲突目标。`ReadingProgress` 表因重写 `primaryKey => {bookPath}` 不受此坑影响。

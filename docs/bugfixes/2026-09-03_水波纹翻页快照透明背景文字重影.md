# 水波纹翻页动画：快照透明背景导致文字双重重影（v16 系列九轮迭代真因）

> 日期: 2026-09-03
> 影响: 水波纹（ripple）翻页动画自 v16 Shader 方案引入 `ui.Image` 快照以来，纯文字页持续出现"上下纹理内容重叠"（双重文字重影），图片页"碰巧正常"；并伴随动画中/完成后色差。历经 v16.1~v16.9.2 共九轮架构级返工（方向反转、三段式、波浪 clip、缩放崩解等）均未根治。
> 状态: ✅ 已解决（v16.9.3）

---

## 症状

1. **纯文字页翻页动画中出现"当前页文字与下一页文字重叠"的重影**；图片页反而正常
2. 动画过程中上下页颜色不一致；**动画完成后还有一次颜色跳变**（仿真翻页 CurlPainter 无此问题）
3. 早期版本还伴随：新页过早出现、细白线、方向反转、块内垂直撕裂等（多为九轮迭代中引入/修复的次生问题）

## 真正根因（v16.9.3 锁定）

### 根因 1（核心）：`_pageToImage` 快照没有画纸色底 → 快照透明背景

`PageContentRenderer.paintPage` 的接口契约（注释明确）：

```dart
/// 绘制背景与 entries（**不含纸色底——调用方按需自绘**）
static void paintPage(...)
```

- 正式页面渲染：`reader_page_widget.dart` 的 `PagePainter.paint` 先 `drawRect(paperColor)` 再调 `paintPage` ✅
- 仿真翻页 `curl_painter.dart`：同样自画 `_paperColor` ✅（这就是 CurlPainter 从不出问题的原因）
- **水波纹 `_pageToImage`（page_turn_composer.dart）：直接调 `paintPage`，没画纸色底 ❌**

→ 快照 = **透明背景 + 文字/图片**。翻页动画是两层快照叠放：

```
层1: 新页快照（透明底 + 下一页文字）
层2: 旧页快照方块（透明底 + 当前页文字）
```

两层文字笔画之间的像素都是透明的 → **互相透叠 = 双重文字重影**。
图片页中图片内容不透明，盖住了下层 → "碰巧正常"。
透明底快照与"有纸色底的实际渲染"色调不同 → 动画中/完成后的颜色变化。

### 根因 2（次生）：shader 逐像素波浪 used `fragCoord.y`，崩解判定却是块级

同一方块内上下像素的 rowBoundary 相差最大 ~45px（波长 120px / 块 28px）→ 方块被
垂直撕裂（"上下方向消解"）。修复：rowBoundary 用 `blockCenter.y`（块级）。

### 根因 3（次生）：jitter 恒为正使旧页侧近线方块"抢跑"崩解

`jitter = h0 * 0.15` 恒为正，在 sweep 公式中使**两方向**旧页侧 12.6px 内的方块
提前崩解。修复：jitter 恒为减法（只推迟、不提前）。

## 修复方案

### 修复 1（核心）：快照补纸色底 + 常量公开化同源

```dart
// page_turn_composer.dart _pageToImage 内：
canvas.drawRect(Offset.zero & size, Paint()..color = PageContentRenderer.paperColor);
```

`_paperColor` 从 `PagePainter` 私有常量公开为 `PageContentRenderer.paperColor`
（static const），正式渲染 / CurlPainter / 水波纹快照三处同源，杜绝常量漂移。

### 修复 2：shader 波浪改块级（v16.9.2）

`rowBoundary` 用 `blockCenter.y` 计算；boundaryX 行程加余量
（margin = waveAmp + blockSize×SWEEP_RANGE），t=0 时最右方块完整、t=1 时最左全崩解。

### 修复 3：两段式缩放崩解 + 微渣消除 + jitter 减法（v16.9.3）

```glsl
// sweep 0→0.6 保持完整；0.6→1.0 快速崩解（scale 1→0）
float collapse = clamp((sweep - 0.6) / 0.4, 0.0, 1.0);
float scale = 1.0 - collapse;
if (scale <= 0.3) { fragColor = vec4(0.0); return; }  // 微渣消除
// jitter 恒减法
sweep = clamp(... - h0 * 0.15, 0.0, 1.0);
```

## 九轮迭代复盘（为什么真因这么晚才被发现）

| 版本 | 猜测的"根因" | 实际 |
|------|------|------|
| v16.1 | 纹理缓存陈旧（跨 pageId 复用旧图） | 修了真问题但不完整（缓存 key 用 setRevision） |
| v16.2 | 架构违背"分界线"设想 → 三段式 | 现象减轻（背景透出的是下层 widget 的当前页矢量，看似无重影） |
| v16.3 | 下坠方向/分辨率/镜面碎片 | 修了真问题（dpr 快照）但色差仍在 |
| v16.4~v16.8 | prev 纹理颠倒/描边/波浪/滑移模型 | 反复在"碎片如何运动"上打转 |
| v16.9 | 透明度淡出（用户定音的单纹理模型） | 模型正确，仍重叠 |
| **v16.9.3** | **快照透明背景** | **真因。图片页不透明盖住下层所以"正常"，文字页笔画间透明互相透叠** |

**教训**：
1. **"图片正常、文字异常"是内容透明度的指纹**——当某症状随内容类型（不透明图片 vs 笔画镂空的文字）出现/消失时，优先怀疑**渲染目标的 alpha 通道**，而不是动画逻辑。
2. **对比法定位**：用户指出"仿真翻页没有这个问题"→ CurlPainter 与水波纹的差异点（自画纸色底 vs 直接调 paintPage）就是嫌疑点，应在第一轮就做差异对照。
3. 复用他人绘制函数时必须读接口契约注释（"不含纸色底——调用方按需自绘"写得很清楚）。
4. 九轮里每次修复都有真实收益（方向/撕裂/微渣），但架构返工掩盖了共性根因——**多次"修好又坏"时应回到最小复现，对比正常与异常路径的全部差异**。

## 后续：完成瞬间色差（同日已修复）

**现象 v1**：快照补纸色底后重影消失，但动画完成后仍有一次颜色变化（仿真翻页无此问题）。

**根因 v1**：动画中揭示页（新页）用快照 `drawImageRect` 绘制，完成后 overlay 移除切回
实时矢量渲染——两条渲染路径（光栅化快照重采样 vs 矢量直绘）存在像素级差异。
CurlPainter 全程实时直绘所以从无此问题。

**修复 v1**：对齐 CurlPainter 的无快照直绘原则——`ripple_painter_v16.dart` 层1
（揭示页/新页）改为**实时矢量直绘**（`_paintPage(revealPage)`），不再消费
`revealPageImage`。实时绘制与完成后渲染完全同源 → 完成瞬间零色差。
旧页快照（层2 shader 采样）随动画结束整体消失，不存在残留色差。
`revealPageImage` 字段仅为兼容 composer 传参保留，paint 不再消费。

---

**现象 v2（v16.9.3 修复后）**：动画过程中"上下页颜色不一样"——旧页（shader 采样的带纸色底快照）显示**淡黄米色**，新页（实时矢量直绘）显示**浅绿薄荷色**。两侧纸色底不一致。

**根因 v2**：`PageContentRenderer.paintPage` 契约"不含纸色底——调用方自绘"。实时直绘调
`_paintPage → paintPage` 时漏画纸色底，露出 canvas 默认透明 → 实际呈现的是新页**主题色
或装饰图**（浅绿），与旧页快照带的 `_paperColor`（淡黄）色差明显。
首次修复时只把"快照画纸色底"做了，忘了"实时直绘路径同样需要"——v16.9.4 才补全。

**修复 v2**：`ripple_painter_v16.dart` 层1 与 fallback 直绘路径在调 `_paintPage` **前**先
`canvas.drawRect(paperColor)`，与 `PagePainter.paint` / `CurlPainter` 三处同源。

**教训补强**：`paintPage` 契约陷阱 = "绘制背景与 entries"——"背景"指 EPUB 装饰页背景图
（`backgroundHref`），**不包含阅读器主题纸色底**。任何调用方若漏画 paperColor 都会
露出 canvas 透明 → 主题色/装饰图与期望纸色不一致。`PageContentRenderer.paperColor` 公开化
（v16.9.3）正是为三处同源防漂移，但**必须在每个调用点都先画**。

**统一调用模板**：
```dart
canvas.drawRect(Offset.zero & size, Paint()..color = PageContentRenderer.paperColor);
PageContentRenderer.paintPage(canvas, page, size: size, onImageNeeded: ...);
```
所有"实时画一页"的代码点（`PagePainter.paint` / `CurlPainter._paintPage` / `RipplePainterV16._paintPage` / `page_turn_composer._pageToImage`）现都已对齐此模板。

## 后续：完成瞬间闪烁（v16.9.5，同日修复，✅ 用户实测通过 2026-09-03）

**现象**：前后页颜色一致后，动画完成瞬间仍闪烁一下。

**根因（双缺陷叠加）**：
1. **短路/fallback 直绘漏纸色底**：`RipplePainterV16.paint` 的 `progress>=0.999` 短路、
   `progress<=0.001` 短路、shader 未就绪 fallback 三条路径直接调 `_paintPage`（无纸色底）。
   仿真翻页同类 bug（`2026-08-28_翻页动画完成瞬间纹理闪烁震荡TickerTrailing帧残迹.md`）
   的 trailing 帧（progress 回退 0.9996~0.9999）恰好命中 `>=0.999` 短路 → 无纸色底的新页
   闪一帧 → 切正式渲染（带纸色底）→ 闪。
2. **渲染参数不一致**：`_paintPage` 用默认参数（fontSize 18/lineHeight 1.5/applyTitleBold false），
   正式渲染用 notifier 同源值——用户设置非默认时动画中新页内容与完成后不同 → 内容跳变。

**修复（v16.9.5）**：
- `RipplePainterV16` 新增 5 个渲染参数字段（applyBold/applyItalic/applyTitleBold/
  baseFontSize/baseLineHeight），composer 传 notifier 同源值（对齐 `page_turn_composer.dart:1055`
  CurlPainter 范本）
- `_paintPage` 统一模板：**先画纸色底、再按参数调 paintPage**——三条短路/fallback 路径
  全部自动修复
- 层1/fallback 中之前显式画的 paperColor drawRect 删除（由 `_paintPage` 统一）

**工程约束（延伸 8-28 报告）**：任何"以 controller 进度做完成判定的短路路径"，其直绘
输出必须与**正式渲染逐像素同源**（纸色底 + 渲染参数），否则 trailing 帧必闪。

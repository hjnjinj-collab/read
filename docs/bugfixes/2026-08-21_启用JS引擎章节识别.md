## 问题分析

### 用户反馈的问题

1. **章节内容包含上一章结尾** - "他们的认知。" 不应该出现在第248章开头
2. **必须使用 JS 引擎的章节识别** - 不要用旧的正则表达式

### 根本原因

**问题1**: 代码强制使用旧的正则表达式
```rust
// txt_parser.rs 第994行
fn extract_chapters(&self) -> Vec<RawChapter> {
    match &self.content {
        Some(content) => {
            // ❌ 强制使用旧正则
            Self::extract_chapters_static(content)
        }
        None => Vec::new(),
    }
}
```

**问题2**: `js-engine` feature 默认没有启用
```toml
# book_parser/Cargo.toml
[features]
default = []  # ❌ 默认不启用 js-engine
js-engine = ["rquickjs"]
```

**问题3**: 之前的章节起始位置修改导致行号计算错误
- 修改了 `start_pos` 指向内容行
- 但 `calculate_line_number()` 根据内容行偏移计算出内容行号
- 导致 `build_cleaned_chapter_cache()` 中的 `line_number + 1` 跳过了一行

## 修复方案

### 修改1: 启用 JS 引擎章节识别

**文件**: `rust/crates/book_parser/src/txt_parser.rs`

```rust
// 修改前
fn extract_chapters(&self) -> Vec<RawChapter> {
    match &self.content {
        Some(content) => {
            // TODO: 等 JS 引擎性能优化后再启用
            // Self::extract_chapters_with_new_extractor(content)
            
            // 暂时使用旧正则（快速）
            Self::extract_chapters_static(content)
        }
        None => Vec::new(),
    }
}

// 修改后
fn extract_chapters(&self) -> Vec<RawChapter> {
    match &self.content {
        Some(content) => {
            // 使用 JS 引擎的章节识别
            #[cfg(feature = "js-engine")]
            {
                Self::extract_chapters_with_new_extractor(content)
            }
            
            // 如果没有启用 js-engine feature，使用旧正则
            #[cfg(not(feature = "js-engine"))]
            {
                Self::extract_chapters_static(content)
            }
        }
        None => Vec::new(),
    }
}
```

### 修改2: 默认启用 js-engine feature

**文件**: `rust/crates/book_parser/Cargo.toml`

```toml
# 修改前
[features]
default = []
js-engine = ["rquickjs"]

# 修改后
[features]
default = ["js-engine"]
js-engine = ["rquickjs"]
```

### 修改3: 回退章节起始位置修改

**文件**: `rust/crates/book_parser/src/txt_parser.rs`

恢复 `extract_chapters_static()` 和 `extract_chapters_mmap()` 中的 `start_pos` 计算：

```rust
// 保持 start_pos 指向标题行起始
chapters.push(RawChapter {
    title: trimmed.to_string(),
    start_pos: line_start,  // 指向标题行
    end_pos: 0,
});
```

**原因**：
- `build_cleaned_chapter_cache()` 中已经有 `line_number + 1` 逻辑
- 这会正确跳过标题行，从内容第一行开始
- 如果我们提前修改 `start_pos`，会导致行号计算错误

## JS 引擎章节识别的优势

### 1. 更准确的章节识别

**旧正则**：
- 固定的模式匹配
- 容易误识别（"第一天"、"第一次"等）
- 无法处理复杂格式

**JS 引擎**：
- 支持自定义规则脚本
- 上下文感知（前后行分析）
- 可以过滤误识别

### 2. 正确的章节边界

**ChapterExtractor.build_chapter_info()** 的逻辑：
```rust
// 章节内容起始：标题行之后
let start_offset = {
    let mut offset = 0;
    for i in 0..=js_chapter.line_number {  // 包含标题行
        offset += lines[i].len() + 1;
    }
    offset  // 指向标题下一行的起始
};

// 章节内容结束：下一章标题之前
let end_offset = {
    let mut offset = 0;
    for i in 0..next_chapter.line_number {  // 不包含下一章标题
        offset += lines[i].len() + 1;
    }
    offset  // 指向下一章标题行的起始
};
```

这确保：
- ✅ 章节内容**不包含**标题行
- ✅ 章节内容**不包含**下一章标题
- ✅ 章节边界准确

### 3. 与净化缓存的配合

净化缓存流程：
```
1. parse() 调用
   ↓ 使用 JS 引擎识别章节
2. 提取 chapters（字节偏移，包含标题行位置）
   ↓
3. build_chapter_metadata_from_chapters()
   ↓ 将字节偏移转换为行号（标题行的行号）
4. build_cleaned_chapter_cache()
   ↓ 全文净化
   ↓ 构建行号映射
   ↓ start_pos = line_number + 1（跳过标题）✅
   ↓ end_pos = next_line_number（下一章标题前）✅
5. 缓存净化后内容
```

## 可能的问题和解决方案

### 问题1: 如果仍然看到"他们的认知。"

**可能原因**：
1. **内容净化删除了标题行** - 导致行号映射错位
2. **原始文本的标题行格式异常** - JS 引擎识别的行号不准确

**调试方法**：
```rust
// 在 build_cleaned_chapter_cache() 中添加日志
eprintln!("章节 {}: 标题行号={}, start_pos={}, end_pos={}", 
    idx, metadata.line_number, start_pos, end_pos);
eprintln!("内容前50字: {:?}", &cleaned_content[start_pos..start_pos.min(start_pos+50)]);
```

### 问题2: JS 引擎识别失败

如果看到日志：
```
ChapterExtractor 失败，回退到正则表达式
```

**可能原因**：
1. rquickjs 编译问题
2. JS 脚本执行超时
3. 内存不足

**解决方案**：
- 检查 `patch.exe` 是否在 PATH 中
- 增加超时时间（默认 5 秒）
- 检查文件大小（超大文件可能需要更多时间）
